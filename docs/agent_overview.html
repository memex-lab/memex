Memex Agent Architecture

当前所有 Agent 的能力、Prompt 和 Tools 地图

这份页面基于当前代码梳理，不是产品说明稿。重点放在每个 Agent 何时触发、用哪些 prompt、拥有哪些工具、写入哪些数据，以及后续深挖源码的入口。

当前快照

12设置页可配置的内置 Agent ID
5用户输入后自动触发的主链路任务
8+核心 Skill 封装
3自定义/宿主型 Agent 路径
输入管线 Agent 清单 工具矩阵 Prompt 深挖顺序 架构观察

输入处理管线

`MemexRouter._registerEventSubscriptions()` 是主入口。用户提交输入后，系统通过 `GlobalEventBus` 投递持久任务到 `LocalTaskExecutor`，再由对应 handler 创建 Agent。

1. UserInputSubmitted

原始输入写入 Facts，并发布系统事件。

2. analyze_assets

先处理图片/音频、EXIF、GPS、OCR，输出 asset analysis。

3. Cards / PKM / Router

CardAgent 和 PkmAgent 使用媒体分析结果；Post-Card Router 判断是否触发后续 Agent。

4. Comments / Schedule / Clarification

评论在 PKM 后执行；路由按需触发日程聚合和澄清问题。

手动刷新

KnowledgeInsightAgent 和 ScheduleAggregatorAgent 也可由设置页/页面按钮通过对应事件手动刷新。

对话入口

ChatService 默认创建 SuperAgent；角色聊天走 CompanionAgent；自定义 Agent 走 Pure/Memex Skill Host。

Agent 清单

可用搜索或分类筛选。每张卡片都给出源码入口，方便继续读 prompt 和 tools。

Media analysis

Agent ID: analyze_assets
事件任务

对输入中的图片/音频做预处理和多模态分析。它不是 `StatefulAgent` 类，而是一个 LLM 工具型 handler，但在模型设置中作为 Agent 独立配置。

触发

`userInputSubmitted` 后第一阶段执行，后续 Card/PKM/Router 依赖其结果。

核心能力

图片/音频安全检查、EXIF 尺寸和 GPS、反向地理编码、LLM 媒体描述、Google ML Kit OCR。

Prompt

`Prompts.assetAnalysisPrompt()`，带语言指令和图片元数据补充。

输出

写入 `{asset}.analysis.txt` 和可选 `{asset}.ocr.txt`，任务结果包含结构化 asset analyses。

源码
analyze_assets_handler.dartasset_analysis_tool.dartagent/prompts.dart

Cards

Agent ID: card_agent
事件任务

把每条原始输入转成时间线卡片。重点是理解多模态内容、选择 Native Card 模板、填充 `ui_configs`，并保证 `fact_id` 与卡片一致。

触发

`card_agent_task`，依赖 `analyze_assets`；LLM 未配置时回退到 rule-based 模板匹配。

Prompt

`cardAgentSystemPrompt` + `TimelineCardSkill` 的模板/标签说明 + 动态发布时间和 fact 内容。

Tools / Skills

强制启用 `manage_timeline_card`：`get_card_metadata`、`save_timeline_card`。Agent 自身无额外 tools。

边界

只负责 Cards；用户长期记忆以 read-only reminder 形式进入上下文。

源码
card_agent.dartcard promptstimeline_card_skill.dartcard handler

PKM

Agent ID: pkm_agent
事件任务

将输入沉淀进 `/PKM` 的 P.A.R.A. 结构，并把知识化后的 insight 回写到对应卡片。它是当前最强的文件写入型自动 Agent。

触发

`pkm_agent_task`，依赖媒体分析，并通过 `getLastTaskByType('pkm_agent_task')` 串行化，避免并发改 PKM。

Prompt

`pkmAgentSystemPrompt` + `Prompts.pkmSkillSystemPrompt()` + 当前 PKM overview + 用户长期记忆 read-only reminder。

Tools / Skills

`Read`、`BatchRead`、`Write`、`Edit`、`Move`、`Remove`、`LS`、`Glob`、`Grep`；`manage_pkm` 工具：`update_timeline_card_insight`、`skip_pkm_organization`。

边界

文件权限只写 `/PKM`；不允许写 memory。显式“不记/不保存”输入会在进 LLM 前或通过 skip tool 跳过。

源码
pkm_agent.dartpkm promptspkm_skill.dartpkm handler

Insights

Agent ID: knowledge_insight_agent
事件任务

周期性或手动分析 Facts、Cards、PKM 和事件日志，维护 Knowledge Insight 卡片，用图表/地图/摘要呈现用户长期模式。

触发

`knowledgeInsightRefreshRequested` 事件进入 `knowledge_insight_task`；首次运行会要求全量分析。

Prompt

`knowledgeInsightAgentSystemPrompt` + `KnowledgeInsightSkill` prompt + memory read-only prompt + run context。

Tools / Skills

读文件工具、`search_workspace_event_logs`、`getCurrentTime`；`update_knowledge_insight` 工具组用于查、存、删洞察卡和读取用户活动统计。

边界

工作区大部分只读；仅通过 insight skill 写 `/KnowledgeInsights`。允许 subagent clone 做大范围资料收集。

源码
knowledge_insight_agent.dartinsight promptknowledge_insight_skill.dartnative_widgets.dart

Comments

Agent ID: comment_agent
事件任务

让虚拟角色在用户私密时间线下进行短评论，也处理用户对角色评论的回复。它强调角色边界、自然短文本和长期互动连续性。

触发

新输入在 PKM 后跑 `comment_agent_task`；用户回复评论会触发 `process_ai_reply`。

Prompt

`commentAgentSystemPrompt` + `Prompts.commentSkillSystemPrompt()` + 角色 persona、角色记忆、近期互动、PKM/卡片上下文。

Tools / Skills

`persona_comment`：`Read`、`Grep`、`SaveComment`、`SkipComment`；有角色时增加 `MemoryRead/Write/Edit/Remove` 和 `HistorySearch`；回复场景可启用用户级 `append_memories`。

边界

可读工作区，评论写入卡片；角色记忆是 character-level，用户长期记忆只在特定回复场景开启。

源码
comment_agent.dartcomment promptscomment_agent_skill.dartcomment handler

Chat / SuperAgent

Agent ID: chat_agent，运行名通常是 memex_agent
交互/聊天

用户主动聊天的中央 Agent。它先判断意图，再按需调用检索、文件工具或业务 Skill；在不同页面会强制激活特定 Skill。

触发

`ChatService.sendMessage()` 默认创建 `SuperAgent`。时间线详情页会强制 `manage_timeline_card` 和 `manage_pkm`；洞察聊天会强制 `update_knowledge_insight`。

Prompt

`superAgentSystemPrompt` + ChatService 注入的“综合纠错原则/交互准则” + memory prompt；Quick Query 追加只读约束。

Tools / Skills

全工作区文件工具、`search_workspace_event_logs`、`getCurrentTime`、`get_pkm_overview`、memory tools；Skills：洞察、卡片、PKM、系统日历提醒、澄清。

边界

普通聊天可写工作区；Quick Query 只保留 `LS/Glob/Grep/Read/BatchRead/search_event_logs/getCurrentTime/get_pkm_overview`。

源码
chat_service.dartsuper_agent.dartsuper prompt

Companion

Agent ID: companion_agent
交互/聊天

角色私聊 Agent，强调持续关系、自然短回复、角色语气和安全边界。它同时能更新用户级长期记忆和角色级关系记忆。

触发

`CompanionAgent.chat()`，角色聊天界面直接流式调用。

Prompt

`CompanionAgentSkill._buildSystemPrompt()` 动态拼接角色 persona、style examples、user profile、character memories、互动历史和 memory guidance。

Tools / Skills

`companion_chat`：`MemoryRead/Write/Edit/Remove`、`HistorySearch`、`SendActionMessage`；Agent 外层增加用户级 `append_memories`。

边界

角色记忆用于关系/支持偏好；用户级 memory 只记录跨角色长期事实。上下文过长后会触发 `CharacterContextCompressor`。

源码
companion_agent.dartcompanion_agent_skill.dartcharacter_tools_factory.dart

Memory summary

Agent ID: profile_agent，实现类 MemoryAgent
事件任务

批量从已沉淀输入中筛出“值得长期保存的用户属性”，写入用户级 memory。它采取 default-deny 策略，宁可不记也不污染记忆。

触发

`PkmAgent` 成功后把 fact 加入 `MemorySyncService`；累积 5 条触发批处理。

Prompt

`MemoryAgent` 内联 Strict Memory Curator prompt，包含排除清单、纳入清单、同语言规则和澄清策略。

Tools / Skills

用户级 `append_memories`；可用 `ask_clarification` skill 为高价值模糊事实创建问题。

边界

只写稳定身份、偏好、长期资产、习惯、AI 交互偏好；任务、提醒、一次性事件不写 memory。

源码
memory_agent.dartmemory_sync_service.dartmemory_management.dart

Post-Card Router

Agent ID: post_card_router_agent
事件任务

轻量级选择器。它不改数据，只判断新输入是否需要触发日程维护或澄清问题，并把后续任务入队。

触发

`post_card_router_task`，依赖 `analyze_assets`，priority 为 -1。

Prompt

`postCardRouterSystemPrompt`：要求保守、一次性调用 `select_downstream_agents`。

Tools / Skills

唯一工具 `select_downstream_agents`，候选为 `schedule_aggregator` 和 `ask_clarification`。

边界

不能写 PKM、不能创建卡片、不能改 schedule；只发事件或入队。

源码
post_card_router_agent.dartrouter promptrouter handler

Schedule

Agent ID: schedule_aggregator_agent
事件任务

维护 `schedule_state` 和日程杂志式呈现。它把输入中的任务、事件、完成、延期、取消等转换为 pending/completed 状态和展示文案。

触发

`scheduleAggregationRequested` 事件，可能来自 Post-Card Router，也可手动刷新。

Prompt

`scheduleAggregatorSystemPrompt` + `Prompts.scheduleAggregatorSkillPrompt()` + 当前 schedule_state + router hint 或近期 schedule 输入。

Tools / Skills

`update_schedule_aggregation`：`get_schedule_state`、`add_pending_item`、`update_pending_item`、`complete_pending_item`、`complete_subtask`、`set_presentation`、`search_completed`。

边界

无外层 tools，所有状态变更走 `ScheduleStateService`。`set_presentation` 可结束 agent loop。

源码
schedule_aggregator_agent.dartschedule promptschedule skill

Ask Clarification

Agent ID: ask_clarification_agent
事件任务

判断是否需要向用户问一个高价值短问题，用来改善未来记忆、实体理解、PKM 组织、卡片修正或洞察质量。

触发

由 Post-Card Router 入队 `ask_clarification_task`。

Prompt

`askClarificationAgentSystemPrompt` + read-only 用户 memory + pending/recent clarification 列表。

Tools / Skills

强制 `ask_clarification`：`create_clarification_request`、`get_pending_clarification_requests`、`get_recent_clarification_requests`。

边界

只创建澄清请求，不写长期 memory；回答后的落库由 Resolution Agent 处理。

源码
ask_clarification_agent.dartask promptask skill

Ask resolution

Agent ID: clarification_resolution_agent
事件任务

用户回答澄清问题后，判断答案是否应转成长期记忆。它负责从“问题/选项/答案/证据 fact”里提取可持久化事实。

触发

`clarificationAnswered` 事件进入 `clarification_resolution_task`。

Prompt

内联系统 prompt：只把稳定事实、偏好、关系、身份、习惯、长期项目上下文写入 memory。

Tools / Skills

用户级 `append_memories`。失败时 handler 有 deterministic fallback，优先使用 option.memory 或 proposed_memory。

边界

不处理 card-only 修正、临时标签或低价值答案；会标记 clarification request completed。

源码
clarification_resolution_agent.dartresolution handlermemory_management.dart

Persona Agent

Runtime name: persona_agent
支撑/宿主

角色设计 Agent。它读用户 PKM 和现有角色列表，生成或更新角色 persona，服务虚拟角色系统。

触发

由角色相关流程调用 `PersonaAgent.run()`，不是主输入管线中的固定订阅。

Prompt

`_buildSystemPrompt()` 内联：强调私密记录场景、情感支持、短文本风格、不要在 persona 中写具体对话示例。

Tools

PKM read-only 文件工具：`LS`、`Glob`、`Grep`、`Read`；角色工具：`GetCharacterPersona`、`CreateOrUpdateCharacterPersona`。

边界

文件工具只能读 PKM；角色更新通过 `CharacterService` / YAML 写入。

源码
persona_agent.dartcharacter_service.dart

Custom Agent Hosts

Host types: pure / memex
支撑/宿主

用户自定义 Agent 的执行宿主。配置文件声明事件、工作目录、skill 目录、host 类型和额外系统 prompt；运行时把事件序列化为 XML 交给宿主 Agent。

触发

`CustomAgentConfigService.registerAll()` 动态订阅任意 `SystemEventTypes`，可 async 或 sync 执行。

Prompt

`PureSkillHostAgent` 使用简短个人助理 prompt；`MemexSkillHostAgent` 使用 Memex 语境 prompt；二者都可追加用户配置的 `systemPrompt`。

Tools

工作目录内文件工具、`search_workspace_event_logs`、`getCurrentTime`、文件系统 Skill 和 `RunJavaScript` runtime。

边界

权限限定在配置的 workingDirectory；媒体引用会从事件 XML 中抽取并以内联多模态 part 传给模型。

源码
custom_agent_config_service.dartcustom_agent_task_handler.dartpure hostmemex host

Prompt 深挖顺序

建议按这个顺序读，不要先陷进某个大 prompt。先理解事件、状态和工具边界，再看语言指令。

1

事件和任务入口

先读 memex_router.dart 的 handler 注册和事件订阅，确认谁会跑、依赖谁。

2

Agent 构造函数

读 lib/agent/ 下每个 Agent 的 `StatefulAgent` 参数：prompt、tools、skills、permission、memory。

3

Skill prompt 和 schema

重点读 agent/prompts.dart 与 agent/skills/，这里定义了大部分 tool schema 和业务流程。

4

上下文装配

最后读 memory、character context、location context 和 run context，理解 prompt 里动态注入的内容。

关键判断：Memex 的 Agent 能力不是只由 system prompt 决定，而是由“事件触发 + 状态恢复 + 文件权限 + skill/tool schema + 动态 reminders”共同决定。读 prompt 时要同步看 tool 的 side effect。

架构观察

这些点适合作为后续改 prompt/tools 前的检查清单。

最容易误解的点 chat_agent 不是一个单独目录，而是 ChatService 默认创建的 SuperAgent；profile_agent 对应实现是 MemoryAgent。
写权限最大 普通 SuperAgent 和自定义宿主可在各自 working directory 写文件；PkmAgent 只写 PKM；KnowledgeInsightAgent 只通过 skill 写 KnowledgeInsights。
最强约束 PkmAgent 串行执行，避免 PKM 并发编辑；CardAgent 会检查保存工具调用和卡片完整性；AskClarificationAgent 要求 aggressive skip。
Prompt 复用 很多 Agent 的短 prompt 只定义角色，真正业务步骤在 agent/prompts.dart 的 Skill prompt 中。
下一步深挖建议 如果要调 Agent 行为，优先定位对应 Skill 的 tool schema 和 stopFlag 逻辑，再改 system prompt。否则模型可能“想做”，但工具边界不允许。
