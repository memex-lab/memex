# SuperAgent 手机能力：记录后的理解与帮助

- 更新时间：2026-09-17
- 基线：`main@1b18637`
- 当前状态：已实现 SuperAgent 的记录关联日历／提醒提案；自动回归完成，iOS 修复包已构建，设备暂不可连接。

## 1. 产品归属

“伙伴”指 Memex 的 SuperAgent：用户正常提交记录后，它理解其中的安排、挂念和信息缺口，按需要查历史、帮助准备或提出手机操作。

Character 是独立的角色陪伴系统。本功能不通过 Character 的感知、主动联系、记忆或私聊实现，不要求用户启用角色。此前误加到 Character 的代码、共享提示词及专用测试已全部撤回，恢复基线行为。

## 2. 当前版本的体验

| 用户输入 | SuperAgent 应如何处理 |
| --- | --- |
| “明天下午三点带妈妈复查。” | 正常保存记录；时间明确且为未来安排时，准备关联该记录的日历建议。用户点击添加后才写入系统 |
| “周五要汇报，担心上次那个数据问题。” | 查找相关历史，提供有依据的准备帮助；没有具体时刻就不猜时间建立日历 |
| “哪天带妈妈去复查。” | 保存挂念，必要时询问，不能擅自决定日期 |
| “昨天三点去复查了。” | 保存过去经历，不准备未来日历建议 |
| “明天下午的复查取消了。” | 不为被取消的安排生成新日历；不能谎称已删除现有系统日程 |
| “帮我建一个明天下午三点的日程。” | 保留原有显式请求路径，直接准备建议，不强制再创建一条生活记录 |

普通记录不必产生任务、追问或日历。SuperAgent 常驻 `search_records` 和 `read_record_evidence` 工具，不依赖角色或额外激活技能。先搜索再核对当前原文，以可打开的来源卡支持回忆、补全与生活帮助；PKM、图片及复杂研究继续使用既有读取工具和 research worker。引用事实时区分来源、推测和未知项，不静默改写原记录。

### 历史查证、回忆、补全与生活帮助 v1

- 历史搜索：按简短关键词检索当前用户已完成、未删除的记录；支持空查询浏览。直接读取来源文件，不依赖索引是否已完成。每页最多读取 200 条、返回 10 个匹配，通过 `next_offset` 继续查询；关键词按 AND 匹配，不是语义向量搜索。
- 原文查证：再次读取匹配记录，把原始 `fact`、附件和生成解读分开返回。生成摘要不是事实证据；卡片时间可能由模型推断，具体事件时间需要核对原文。
- 来源展示：沿用聊天产物的持久化与详情导航，新增 `reference` 操作。聊天显示“追溯”并可打开原记录，不显示“新建卡片”。已删除、未完成、其他用户和非法 ID 不生成来源。
- 回忆：围绕当前记录提到的人、经历或未完事项，给出简短、有出处的历史关联；没有相关证据时不编造。
- 补全：在回复中生成准备清单、草稿或一个必要问题；明确区分已有事实、建议和未知项。不会把建议自动写成用户原话。
- 生活帮助：例如记录“带妈妈复查”后查找上次就诊，依据记录提示已有报告或待问事项；时间明确时准备关联记录的日历建议。建议是否有用及何时触发由 SuperAgent 模型判断。
- 只读查询可以使用这两个读取工具；设备写入仍保持原有确认边界。无新的后台主动触达，也不连接 Character。

## 3. 已实现的链路

```text
正常记录入口 → SuperAgent → Card/PKM workers 完成记录
                              ↓ 明确未来安排
                 manage_calendar_and_reminders
                              ↓ fact_id
                  SystemActionService（待确认提案）
                        ↙                 ↘
                  聊天产物             来源记录附件
                              ↓ 用户点击添加 + 系统权限
                      NativeActionService
                              ↓
                   iOS / Android 日历或提醒
```

- SuperAgent 主提示词与 Skill 描述允许从明确的未来安排提出建议，不再要求必须出现“创建日历”指令。
- `create_calendar_event` 和 `create_reminder` 接受可选 `fact_id`。从记录产生的建议必须传入已完成保存的真实 ID；纯日程请求仍可不传。
- `SystemActionService.prepareForRecord` 经 `FileSystemService` 核对所属用户的来源记录已完成且未删除，并拒绝无效 ID、过去或缺失的时间。
- 提案复用现有 `SystemActions` 和 `CardAttachmentFactory`，因此同时支持聊天产物、来源记录附件和待办入口，无需新的 Character UI。
- 相同用户、来源记录、操作类型及规范参数生成同一个提案 ID。并发或重试不重复插入；已拒绝／隐藏／完成的原提案不会变成新待确认卡。参数实质改变属于另一个提案，避免仅为了重新询问而换参数。
- 提案已有持久确认界面，准备提案时不再额外等待一次会话内确认。原生写入仍需用户点击和 OS 权限。
- Quick Query 继续移除整个写入 Skill；工具执行层额外拒绝 `read_only`，防止泄漏的工具绕过。
- 确认执行重新读取数据库状态；已拒绝的旧卡不能执行，已完成的旧卡不会再次写入；同进程并发确认共用执行结果。
- 未修改数据库表、生成代码、原生日历实现或用户历史数据。未引入外部依赖。

## 4. 当前边界

- 本轮包括有来源的回忆与回复内生活帮助，以及设备提案、关联和确认写入；不等于实现完整手机操作平台。
- 尚无系统日历查询、已有事件修改／取消、外部记录标识跟踪或独立系统通知扩展。
- Android 现有提醒用带提醒的日历事件实现，不宣称已连接独立待办 App。
- 原生桥接仍返回布尔结果。若原生写入完成但持久状态写入前崩溃，尚不能可靠核对结果，不能宣称具备跨崩溃恰好一次执行。
- 明确／模糊／历史／否定意图的判断由模型和提示词完成；自动化测试验证工具链及持久状态，不替代真实模型语义评测。
- 来源记录后来被更正或删除时，尚无统一的提案失效传播；不能把原有提案当成外部日历的实时同步副本。

## 5. 后续执行计划

1. 完成当前闭环：正常记录触发建议，确认后实际写入；用未来安排、历史事件、否定安排、模糊愿望做真实模型评阅。
2. 升级执行回执：保存外部对象标识，处理未知结果、跨重启核对、来源变更、用户／工作区切换；再支持查日历、改期和取消。
3. 补充系统通知及返回原记录／对话；区分日历提醒与 Memex 通知，避免重复触达。
4. 按具体生活帮助需要扩展健康等能力。导航、通用屏幕操作及 Character 接线不属于本轮。

实现始终沿用既有服务与 owning tools：Router 保持薄层、受管理数据不绕开所属服务、UI 使用既有附件工厂。未来状态和界面扩展补相应单元、Widget 和跨层测试。

## 6. 验证与试用

自动回归包括：

- 显式日历／提醒请求保持可用，时间和参数验证不退化。
- 已保存记录 → 真实 Skill 工具调用 → 提案落盘 → 聊天产物及来源附件。
- 同一提案重试、拒绝后重试、未完成来源及用户隔离。
- 确认模式只准备待确认卡；只读模式即使调用泄漏工具也被拒绝。
- Widget 跨层测试：保存来源 → SuperAgent Skill → 附件工厂 → 添加按钮 → 原生桥接替身 → completed；无任何角色初始化。
- 同进程重复确认只写一次，过期的已拒绝卡不能执行。

手工试用：在正常记录入口输入“明天下午三点带妈妈复查”，检查记录保存后是否出现日历建议；点击“添加到日历”，授权后到系统日历核对。另测试“昨天去过”“以后找时间去”“明天的安排取消了”，不应生成新的日历建议。

### 历史帮助 v1 试用脚本

1. 先记录“今天陪妈妈复查，医生让下次带上检查报告”。再记录“明天下午三点陪妈妈复查”。预期：正常保存，能引用上次记录，给出带报告等有依据的准备帮助，并准备日历建议；点击后才写入系统。
2. 询问“上次复查让带什么？”预期：引用原文，出现可打开的追溯卡。
3. 记录“周五汇报，担心上次的数据问题”。预期：搜索已有汇报记录、整理准备建议，未知具体问题时询问；不编造会议时刻。

### iOS 日历确认交互修订

- 日历建议按钮变为“在日历中确认”：通过 EventKitUI 展示系统 `EKEventEditViewController`，预填标题、起止时间、地点和备注，用户可以调整后保存。
- iOS 不再直接调用 `eventStore.save(event)`。仅收到系统编辑器 `.saved` 回调后标记建议 completed；取消返回独立结果并保留 pending，不显示失败。重复打开由原生单编辑器保护及服务 in-flight 合并处理。
- iOS 17+ 不请求日历访问权限；旧版 iOS 由原生兼容路径请求权限后展示编辑器。Flutter 日历卡不再预先阻挡 iOS 用户。提醒事项与 Android 路径保持原有实现。
- 系统编辑页在 Memex 上方呈现，不是通过 URL 跳转到独立 Calendar App。中文与英文文案已更新，其余语言新增文案使用生成器英文回退。
- 目标回归 52 项通过，包含预填参数、取消与错误区分，以及 iOS 无权限预弹窗、取消后重试、保存后完成的跨层 Widget 测试。原生编译已通过；实际系统编辑页仍需手机试用。
