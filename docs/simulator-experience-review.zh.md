# Memex iOS 操作实测：从第一次记录到恢复备份

2026 年 11 月 28 日。审查对象是 `codex/home-four-tabs` 在基线 `1c91f2a25d1a` 上的工作树，含当时的未提交改动。本文补充[架构与代码审查 #502](https://github.com/memex-lab/memex/issues/502)。

**影响发布判断的新发现是，AI 首次提交的卡片参数有误时，应用会删除这条记录预留的 ID。** 用户会看到动作已完成，随后被要求确认一串自己从未输入过的 ID。这个问题在已经连通模型的情况下发生，涉及最常用的记录入口。建议将“同一条记录校验失败后能修正并保存”加入稳定版发布条件。

## P1　首次参数校验失败，随后无法用同一 ID 补救

在设置页选本地 Ollama，从模型列表选中 `qwen3:4b-instruct`，文本连接测试返回 `ok`（10,131 ms）。保存配置后，通过首页中间的加号，先后输入三条记录。

| 输入 | 工作区里实际发生的事 | 用户看到的结果 |
| --- | --- | --- |
| “QA502RIDE. I cycled 12 km today.”，要求记录骑行 | 已分配 ID。第一次保存缺少 duration 模板的 `elapsed`；第二次带上该字段时，工具返回记录不存在。 | 动作摘要显示已完成 7 个动作。对话要求用户确认 ID，刷新时间线只有原有示例卡。 |
| “Save a quote: Small steps count. Use a quote card.” | 首次保存有标题和 quote 模板，缺少新卡必填的 `fact`。第二次尝试沿用同一 ID，工具返回记录不存在。 | 动作摘要显示已完成 5 个动作。对话提示记录 ID 无效，未生成结果卡。 |
| 对照输入：指定新卡标题 QA502、原文 Keep going、引言模板，并明确要求首轮同时提交所有必填字段 | 第一次保存成功。工作区多出一份卡片 YAML，SQLite 的卡片全文索引能找到 QA502。 | 对话出现“卡片已生成”。时间线可点击，杀进程重开后详情仍有标题、正文，稍后还有角色评论。 |

前两条都是一次实际运行，模型再次运行可能选择其他模板。**代码层的失败条件可以稳定触发。** 保存工具在校验前把新卡占位标记为可回滚，异常处理会删除占位。下一次调用先检查文件是否存在，直接返回错误。我在临时副本用实际 mint/save 工具做了一个独立 Flutter 用例：预留 ID → 提交缺少 fact 的参数 → 核实占位消失 → 用同一 ID 提交完整有效参数。断言通过，最后一步仍返回 `does not exist`。该用例不依赖模型，也消除了第二次模型调用仍可能有其他参数错误的干扰。登记占位见 `lib/agent/skills/manage_timeline_card/timeline_card_skill.dart:292` · 异常清理见 `lib/agent/skills/manage_timeline_card/timeline_card_skill.dart:628` · 重试时读取卡片见 `lib/agent/skills/manage_timeline_card/timeline_card_skill.dart:280`

**修复验收。** 允许同一轮内纠正参数，结束或放弃整条记录时再清理空占位。用“首次无效、第二次有效”的输入验证最后恰有一张卡，评论和记忆任务各按设计触发一次。在真正保存前，动作面板应能区分工具结束、保存失败和卡片已生成，用户可以直接用原文重试。[失败与真实模型回复截图](review-evidence/ios-2026-11-28/connected.jpg) · [成功保存与重启回读截图](review-evidence/ios-2026-11-28/capture.jpg)

## 首次配置、异常入口与备份恢复

首次使用 Memex 必须先配置 AI。下表保留旧版本的复现过程。旧版跳过配置后能够写入会话，暴露了首次配置入口的缺陷。

在修正后的本地构建上，用全新 iPhone 模拟器完成昵称与存储选择后，应用停在 AI 配置页。此时通过 `memex://quick_note` 打开应用，仍停在配置页。选择本地 Ollama 的 `qwen3:4b-instruct`、同意并保存后，首次记录引导出现；再次冷启动直接进入时间线。

| 场景与判断 | 操作和交叉验证 | 建议验收 |
| --- | --- | --- |
| 首次配置可被跳过 | 空名字提交收到校验提示，输入 Review502 后选择“暂不配置，先逛逛”。欢迎引导要求点中间加号，同时出现“配置未完成”。连续点两次加号没有进入记录页；先跳过引导，再点“继续记录”才回到可操作的首页。[截图](review-evidence/ios-2026-11-28/onboarding.jpg) | 取消或退出服务商配置后仍需完成配置。默认文本模型具备所需凭据后，才能进入首页和首次记录引导。 |
| P2 · 未配置模型时，发送成功保存了会话，时间线没有记录 | 通过 `memex://quick_note` 打开输入页，拒绝完整照片访问，再用系统选择器依次选择图标和花朵图。发送后出现原始错误 `LLM API Key is empty`。刷新时间线未见新卡；重启后重开对话，仍能看到原文和按选择顺序排列的两张图。只读核对会话 JSONL，确认一段文字和两个可解析到实际文件的图片引用。[截图](review-evidence/ios-2026-11-28/offline.jpg) | 首次未配置 AI 时，快捷入口也应停在配置流程。发送前发现配置缺失，应保留输入草稿；本次提交不应生成会话、附件副本或任务。 |
| P2 · 评论已落盘，同时出现模型配置错误 | 在示例卡发表 QA502-COMMENT，看到配置弹窗。关闭提示后评论可见，之后经过备份、删除、恢复和进程重启仍能在详情读到。[恢复后的评论](review-evidence/ios-2026-11-28/restore.jpg) | 单独呈现本地评论提交结果和 AI 后续动作结果，让用户知道是否需要再点发送。 |
| P2 · 备份恢复成功，首页先显示陈旧空态 | 手动生成约 2.9 MB 的备份，先取消一次恢复确认；随后删除这台测试机上的示例卡，确认时间线为空，再恢复同一快照。界面出现恢复前安全快照和完成提示。点确定回首页仍为空，下拉刷新即可看到卡片；杀进程重启后卡片及评论均存在。[截图](review-evidence/ios-2026-11-28/restore.jpg) | 完成提示返回首页时主动重读活动工作区，或在重新加载时显示进行中；同时验证恢复内容与恢复后首次展示。恢复完成路由见 `lib/ui/settings/widgets/backup_restore_page.dart:699` |
| 权限时机 · 还没有选择内容就弹系统授权 | 在本次模拟器环境，首页冷启动和从照片选择器返回时出现来自 CoreSimulatorBridge 的粘贴请求；全程选“不允许粘贴”。首次打开空白输入页就收到照片图库授权请求，拒绝后仍能手动选两张图。[启动](review-evidence/ios-2026-11-28/onboarding.jpg) · [相册](review-evidence/ios-2026-11-28/offline.jpg) | 将建议功能的授权放到可解释的用户动作之后，保留拒绝权限后的手动选择路径。剪贴板提示的发送方与系统策略还需在真机上对照。首页触发点见 `lib/main.dart:1693` |

## 验证口径

- iPhone 17 Pro 模拟器，iOS 26.5，中文界面，全新测试账号 Review502。测试使用系统模拟器点击、输入、手势、照片选择器、深链、终止进程及重新启动。截图来自实际界面；会话、卡片、附件和 SQLite 检查均为只读。
- 构建使用 Flutter 3.50.1、Dart 3.14、应用版本 1.0.39+124、iOS global scheme。在隔离副本切换到 CocoaPods、离线解析依赖，锁文件有 21 项差异；使用仓库提供的模拟器 ML Kit 占位实现。可验证 UI、文本模型与本地数据流，不能据此判断正式构建的 OCR 或图像识别质量。
- 这次只发布报告与截图。实测额外运行了一个针对保存重试的用例，未重跑全量套件与静态分析；前一轮的全量结果保留在 #502。本次未覆盖 Android、物理设备、iCloud 跨设备恢复、真实麦克风或健康传感器。本地 4B 模型的三条输入不能用来估算其他模型的成功率。
